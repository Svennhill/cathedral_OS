## Verdict: Capacitor fits

Capacitor is the right wrapper for this codebase, and it is now scaffolded.

Why it fits:

- **It is a static Vite build.** `npm run build` produces a self-contained `dist/`
  folder with no server code, no API routes, and no server-side rendering.
  Capacitor's model is exactly that: copy a static web build into a native app shell.
- **Asset paths work unchanged.** The app loads files by root paths (`/boot/...`,
  `/audio/...`, `/fx/...`). Capacitor serves the bundle from the root of a local
  origin (`https://localhost` on Android, `capacitor://localhost` on iOS), so those
  paths resolve without edits. This was tested; see "Proof" below.
- **No server dependencies.** The only network-style call is a `fetch` of a bundled
  text file (`/boot/boot_bible_quotes.txt`), which is served locally inside the app.
  Saved state uses `localStorage`, which works in the app's WebView.
- **No code changes are needed.** The app doesn't need to import Capacitor at all to
  run in the wrapper, so the web bundle stays byte-for-byte the same.

Alternatives considered and set aside:

- *PWA only*: there is no App Store listing, and iOS install is clumsy. This could be
  added later alongside the apps.
- *Trusted Web Activity (Android only)*: this wraps the live site and needs network
  access. There is no iOS equivalent, so it doesn't meet the "Android + iPhone" goal.
- *React Native rewrite*: the whole UI would have to be rewritten. Not justified.

### Proof the web app is unharmed

- **The `dist/` output is byte-identical to main.** I built on main, then on this
  branch after a clean `npm ci`. All 141 output files have identical SHA-256 hashes.
- **Vercel is unaffected.** The Vercel projects use the Vite preset on Node 24.x,
  which meets Capacitor CLI's `node >=22` requirement. Nothing in the app imports
  Capacitor, so nothing Capacitor-related enters the web bundle.
- **No app code changed.** Nothing in `src/`, `public/` or `index.html` is
  touched, and the Vite config is unchanged.

### Proof the wrapper can load the app

`npx cap sync` copied the build into both native projects. Each copy holds the same
141 files as `dist/`, plus two empty Cordova shim files that Capacitor adds itself.

I then served the Android copy from a root origin, the way the wrapper serves it,
and loaded it in headless Chromium at phone size (412×915):

- The bezel rendered.
- Pressing **POWER** played the full CRT and boot sequence: video, boot art, quotes
  file, and chimes.
- There were no page errors.
- The only failed request was `/OS/music_OSnolongerplaysfornowuntilideletethissection.wav`.
  That file is missing from `public/` on main as well, so it already fails on the
  live site. It is not caused by the wrapper.

This is a browser test. It is not a real phone. On-device testing is step 4 below.

## (b) Remaining steps, in order

1. ⏭️ **Set up a local build machine.**
   *Why:* native apps can't be compiled in a cloud session. This one had no Xcode,
   and the Android SDK download host is blocked. You need Android Studio (any OS) for
   Android, and a **Mac with Xcode** for iOS. Apple only allows iOS builds on macOS.
   Use the versions listed in Capacitor 8's environment-setup docs.
   If you have no Mac, a cloud Mac CI service (such as Xcode Cloud or Codemagic) is
   the alternative. That choice is ⛔ **BLOCKED-FOR-OWNER**, because it means an
   account and possibly a cost.

2. ⏭️ **First native build (debug).**
   *Why:* this is the first proof that the projects compile. Run these on that machine:
   ```bash
   npm ci
   ```
   ```bash
   npm run mobile:sync
   ```
   ```bash
   npm run mobile:android
   ```
   ```bash
   npm run mobile:ios
   ```
   The last two open Android Studio and Xcode, where you press Run on an emulator or
   simulator. The iOS simulator needs no Apple account. Run `npm run mobile:sync`
   again after every web change. The apps carry a copy of the build and do not load
   the live site.

3. ⛔ **BLOCKED-FOR-OWNER: Final icon and splash art.**
   *Why:* both stores reject placeholder icons. Replace the five files in `resources/`
   (sizes are listed in `resources/README.md`), then run:
   ```bash
   npx @capacitor/assets generate --assetPath resources
   ```
   Commit the regenerated icons in `android/` and `ios/`. Only you can approve the
   brand art.

4. ⏭️ **On-device test pass.**
   *Why:* WebViews differ from desktop browsers in a few places that matter here.
   Check each of these on a real phone:
   - **Audio.** Boot chimes and SFX play after you press POWER. Mobile WebViews
     block sound that isn't triggered by a tap.
   - **Notch and status bar.** The bezel doesn't sit under the notch or status bar.
     Android 15+ draws apps edge to edge. If there is overlap, fix it in the native
     or wrapper config first. A CSS fix would also change the website, so it needs
     its own PR.
   - **Saved state.** Case progress (`localStorage`) survives an app restart.
   - **Light mode.** The page sets `color-scheme: light dark`, so a phone in light
     mode shows a light background around the bezel. The phone browser already does
     this today; decide whether you want it in the app.
   - **Orientation.** Decide portrait-only or free rotation (see decision 2).

5. ⏭️ **Shrink the app bundle (recommended, needs your OK).**
   *Why:* the app ships everything in `public/`, about 139 MB. Roughly 112 MB of
   that isn't referenced by its literal path anywhere in `src/`. The biggest items
   are `fx/old/`, `fx/test/`, `fx/crt_on(old).mp4` and the 21 MB `OS/music_OS.wav`.
   Some files may be loaded by a constructed path name, so confirm before removing
   anything. This size is under Google Play's base download limit, but it makes
   installs slow. There are two options:
   - Delete the unused files from `public/`. This also shrinks the website, so it
     is a web change and needs its own PR.
   - Add a mobile-only prune step to `mobile:sync`. The website is untouched.

   ⛔ **BLOCKED-FOR-OWNER**: you decide which files are truly unused.

6. ⛔ **BLOCKED-FOR-OWNER: Developer accounts.** *(Purchase nothing until you choose to.)*
   *Why:* the stores only accept apps from enrolled developers, in the legal name
   that will be shown on the store listing.
   - **Apple Developer Program, $99/year**, enrolled as an individual in your own
     legal name. Apple verifies identity, and approval can take a few days.
   - **Google Play Console, $25 one time**, as a personal account in your own name.
     Google verifies identity.
   - **Google rule for new personal accounts:** you must run a **closed test with
     at least 12 testers, opted in for 14 consecutive days**, before you can publish
     to production. Line up testers early. This is the longest calendar item.

7. ⛔ **BLOCKED-FOR-OWNER: Code-signing identities.**
   *Why:* stores install only signed builds, and the keys prove the updates come from you.
   - **Android:** generate an upload keystore (Android Studio → Generate Signed
     Bundle). Back it up offline. **Never commit it.** Enroll in Play App Signing.
   - **iOS:** in Xcode, sign in with your Apple ID, then pick your Team under
     *Signing & Capabilities*. Xcode creates the distribution certificate and
     provisioning profile. Do not commit any certificates or `.p12` files.

8. ⛔ **BLOCKED-FOR-OWNER: Store listings and required disclosures.**
   *Why:* both stores require these before review.
   - **Privacy policy URL.** Required even if no data is collected. Hosting it on
     reliquarycodex.com would be a web change, so it needs its own PR.
   - **Apple App Privacy answers and Google Data Safety form.** The app stores
     settings and progress only on the device.
   - **Age or content rating questionnaires.**
   - **Screenshots** at each store's required device sizes, plus the description
     and category.
   - **Support URL or contact email.**

9. ⛔ **BLOCKED-FOR-OWNER: Release builds and submission.**
   *Why:* only the account holder can upload builds and submit them for review.
   - **Android:** build a signed `.aab` and upload it to the closed test track
     (step 6). After 14 days, request production access.
   - **iOS:** in Xcode, choose Product → Archive, upload to App Store Connect, then
     run a TestFlight beta and submit for review.
   - **Version numbers:** Android `versionCode`/`versionName` are in
     `android/app/build.gradle` (currently 1 / "1.0"). iOS version and build are in
     Xcode (currently 1.0 / 1). Increase them on every upload.

10. ⏭️ **Optional later.**
    - A CI job that builds a debug APK on each PR.
    - Native plugins, such as `@capacitor/preferences`, if you want saves stored more
      durably than WebView storage (iOS can clear WebView data when space runs low).
    - Web code that imports Capacitor would affect the web bundle, so each of these
      needs its own reviewed PR.

## Open decisions and risks

1. **[Risk] Apple guideline 4.2, "minimum functionality".** Apple rejects apps that
   are just a repackaged website. Cathedral ships its full content offline and is
   heavily interactive, which works in its favor. Still, write the review notes to
   stress that it is a self-contained app, not a site link. Have a fallback ready,
   such as a native share button or a native haptic on the power switch, in case
   the first review pushes back.
2. **[Decision] Orientation.** The bezel layout is portrait-shaped. ★ I recommend
   locking to portrait on phones. It is native config only (`AndroidManifest.xml`
   and Xcode *Deployment Info*), so the website is untouched.
3. **[Note] App identity is hard to change.** `com.reliquarycodex.app` becomes
   permanent once the app is published to either store. Confirm it before the first
   upload. Until then it is easy to change in `capacitor.config.ts` and both
   native projects.

## How the website stays safe going forward

- Vercel builds only with `vite build`. It never reads `android/`, `ios/`,
  `resources/` or `capacitor.config.ts`.
- Capacitor is installed but never imported by the web code, so the web bundle
  doesn't include it.
- The bundle copies inside the native projects are gitignored. Regenerate them with
  `npm run mobile:sync`.
